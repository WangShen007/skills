# O 奖对标质量门槛（可执行检查清单）

> 这是“写作与交付检查”的操作化版本：每次准备进入下一阶段前，都对照打钩。
> 说明：硬性规则以当年题面/官方说明为准；本文件融合了你的本地笔记中的高频经验。

## A. 硬性合规（Fail fast）

- [ ] 页数：**不超过官方上限**（你本机官方缓存显示当前为 25 页，且包含 Summary/目录/参考文献/附录/代码等；以当年规则为准；AI Use Report 通常追加在 25 页后且不计入）
- [ ] 语言与格式：英文 PDF、字号/页边距等符合题面要求
- [ ] Summary：第一页、可独立阅读、结构完整（见 B）
- [ ] 文件可打开、图表不糊、公式/符号不乱码、引用不缺失

## B. Summary（第一页决定生死）

> 目标：1 页内“让评委立刻知道你做了什么、结果是什么、为什么可信”。

- [ ] 1 句话清晰重述问题（不复述题面细节）
- [ ] 给出整体方法框架（1 句话 + 1 个短列表/流程）
- [ ] 关键假设（1–3 条，且是“决定模型形态”的那种假设）
- [ ] **定量结果**（至少 2–4 个数字 + 指标名 + 单位/范围）
- [ ] 明确结论/建议（可执行）
- [ ] 可信度一句话：验证/对照/敏感性结论（哪怕是很短的一句）
- [ ] 不出现空话：不写“we did a lot of work / very important”等无信息句

## C. 主体结构（评审阅读路径友好）

建议高频结构（不强制）：Introduction/Restatement → Assumptions & Notation → Data → Model → Results → Analysis → Sensitivity/Validation → Strengths & Weaknesses → Conclusion → References/Appendix

- [ ] 子问题逐一“点名”并闭环（模型/结果/结论都对应题目问法）
- [ ] 变量表（Notation）含单位、与图表一致
- [ ] Assumptions 每条都能辩护（数据/常识/文献/敏感性）
- [ ] Data 章节说明字段含义、预处理、缺失与异常处理
- [ ] Model 给出清晰数学表达或算法流程图（读者可复现）
- [ ] Results 是定量表述（图表 + 指标 + 对照）
- [ ] Analysis 解释“为什么这样”“边界在哪”“什么时候会失效”

## D. 可信度与加分项（O 奖常见）

至少完成其一，最好二者兼备：
- [ ] Sensitivity Analysis：关键参数扰动/情景对比，结论稳定性明确
- [ ] Validation：对照基线/外部数据/已知规律/交叉验证/回测等

额外加分但不要硬凑：
- [ ] 多方案对比与取舍（trade-off）
- [ ] 不确定性讨论（误差来源、数据偏差、模型适用范围）

## E. 图表质量（图表是证据链）

原则：**每张图回答一个问题**；正文必须引用并解释。

- [ ] 开头有模型结构/流程图（帮助评审快速理解）
- [ ] 至少包含：趋势/分布/相关或拟合/结果对比/稳健性（按题型选择）
- [ ] 坐标轴单位齐全、图例清晰、配色可读（色盲友好优先）
- [ ] 输出分辨率够（建议 300dpi 或矢量 PDF/SVG）
- [ ] 图注写“结论”，不只写“what”，要写“so what”

## F. 自评（Strengths & Weaknesses）

不要只写“我们很强/我们很弱”，要可执行：
- [ ] Strengths：与评审关注点对应（建模/分析/沟通/覆盖度）
- [ ] Weaknesses：承认关键限制，并给出可改进方向或补救实验

## G. 复现性（不是科研论文，也要让人信）

- [ ] 给出数据来源与版本（下载日期/链接/口径）
- [ ] 给出主要步骤（伪代码/流程图/关键参数表）
- [ ] 关键结果可在 `analysis/` 里一键复现（至少你自己能跑通）
